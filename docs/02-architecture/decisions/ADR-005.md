# ADR-005 — Cliente é identificado por e-mail, sem exigir conta

## Contexto

Agendar uma visita é o fluxo principal do produto, e forçar criação de conta antes disso é atrito
que o negócio não quer pagar.

## Decisão

`POST /appointments` é público. O cliente informa nome/e-mail/telefone; o sistema acha o `customer`
por e-mail ou cria um novo, sem tocar no perfil de uma conta já existente. O agendamento guarda uma
cópia própria desses três campos, independente do que existe em `users`.

## Consequências

- Permite reconhecer cliente recorrente (mesmo e-mail, agendamentos anteriores) sem duplicar
  cadastro, e sem exigir senha pra agendar.
- Uma nova solicitação nunca sobrescreve o perfil da conta — só o snapshot do próprio agendamento
  muda.
- Confirmação/cancelamento por token de e-mail (sem login) é consequência direta: o cliente nunca
  teve senha pra começo de conversa.
