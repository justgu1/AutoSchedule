# ADR-006 — Token de confirmação nasce só quando o e-mail sai

## Contexto

`Appointment` tem um token de confirmação opaco que o e-mail carrega, sem exigir login do cliente.

## Decisão

O token só é gerado dentro de `markConfirmationSent()`, nunca em `request()` (criação). Texto puro
gerado antes de existir e-mail pra levá-lo seria descartado sem ninguém poder usá-lo depois — só o
hash é persistido, e só a partir do envio `expires_at` passa a valer.

## Consequências

- `pending` sem e-mail ainda enviado não tem prazo de expiração — não faz sentido expirar uma
  reserva que o cliente nem foi convidado a confirmar.
- O timing do envio (handoff do agendamento anterior + 15min de preparo, ou na hora se nada
  bloqueia) fica isolado numa rotina agendada, sem acoplar `CreateAppointment` a essa lógica.
