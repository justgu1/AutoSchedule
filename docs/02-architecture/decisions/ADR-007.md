# ADR-007 — `search_vector` é coluna gerada, nunca trigger nem escrita da aplicação

## Contexto

A busca de veículo precisa recalcular o índice de texto toda vez que marca/modelo/versão/ano/
descrição mudam.

## Decisão

`vehicles.search_vector` é `GENERATED ALWAYS AS (...) STORED` — o PostgreSQL recalcula sozinho a
cada escrita, e a coluna fica fora de `COLUMNS`/`toParams()` do repositório (não aceita escrita
direta).

## Consequências

- Nenhum caminho de escrita futuro pode esquecer de recalcular — trigger é um segundo lugar onde
  lógica mora, invisível ao repositório; escrita pela aplicação exige que todo caminho lembre, e
  esquecer produz veículo que nunca aparece na busca, em silêncio.
- Dicionário `simple`, não `portuguese`: stopword comeria versão curta ("S", "Up!") e stemming
  quebraria nome próprio ("Corolla" viraria `corol`) sem ganhar recall — quem cobre erro de
  digitação é o `pg_trgm`, não o dicionário.
