# ADR-010 — `client_credentials` com dono autentica como o próprio dono

## Contexto

Credenciais de API self-service (`AC-*`) precisam de alguma identidade pra rodar contra as rotas
protegidas por role/RLS — mas o sistema não tem escopo granular próprio pra client OAuth.

## Decisão

Quando o client autenticado tem `owner_user_id`, `IssueServiceToken` resolve o `User` dono e emite
o token com `subject = owner.id`, `role = owner.role` — não `subject = client_id`, `role = null`
como o client de sistema (`autoschedule-web`/`autoschedule-service`) sempre teve.

## Consequências

- RLS e `RoleMiddleware` funcionam sem nenhuma mudança: o token m2m parece, pro resto do sistema,
  uma sessão normal do dono.
- Client herda a permissão do dono por inteiro — sem sistema de escopo próprio nesta entrega (não
  é regressão: escopo hoje já não é imposto em lugar nenhum do código existente).
- Dono `trashed` ou client revogado precisam negar o login explicitamente (AC-003) — sem isso, um
  dono desativado continuaria acessível via a própria credencial que ele mesmo gerou.
